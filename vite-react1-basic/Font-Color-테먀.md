# Font-Color-테마

사용자마다 각기 다른 작업 환경과 취향을 가지고 있으니, 이 3가지 테마를 선택지로 제공하는 것은 정말 훌륭한 전략입니다. 특히 `HyperPane`처럼 하루 종일 들여다봐야 하는 관리 시스템에서 **"나에게 맞는 색상"**을 고를 수 있다는 건 업무 만족도에 큰 차이를 만들죠.

이를 구현하기 위해 우리가 준비해야 할 **테마 스위칭 시스템**의 구조를 정리해 드립니다.

---

## 🎨 HyperPane 테마 선택 시스템 설계

### 1. `index.css`에 테마 정의하기

단순히 색상 하나만 바꾸는 게 아니라, `index.css`에 각 테마별 CSS 변수 세트를 미리 선언해 둡니다.

```css
/* index.css */
:root { /* 기본: Soft Luxe Blue (기본값) */
  --background: 210 40% 98%;
  --primary: 221.2 83.2% 53.3%;
  /* ... */
}

.theme-mocha { /* Mocha Mousse */
  --background: 20 15% 95%;
  --primary: 25 25% 52%;
  /* ... */
}

.theme-cyber { /* Cyberpunk Neon */
  --background: 0 0% 0%;
  --primary: 142 100% 50%;
  --foreground: 0 0% 100%;
  /* ... */
}

```

### 2. 테마 선택 UI (Settings)

사용자가 `HyperPane`의 설정 메뉴에서 테마를 고르는 직관적인 UI를 제공합니다.

* **컴포넌트**: shadcn/ui의 `Radio Group`이나 `Select`를 활용합니다.
* **미리보기**: 각 테마의 메인 컬러가 담긴 작은 원(Circle)이나 사각형을 나열하여 직관적으로 선택하게 합니다.

### 3. 상태 유지 (Persistence)

사용자가 테마를 바꾸면 그 정보는 브라우저의 `localStorage`나 사용자 DB에 저장되어야 합니다. 그래야 다음 날 출근해서 다시 로그인했을 때도 **본인이 설정한 테마**가 그대로 유지됩니다.

## 💡 사용자 경험(UX) 포인트

### "창별로 다른 테마?" (HyperPane의 묘미)

우리가 만든 `HyperPane`은 화면이 분할(Split)되는 게 핵심이잖아요? 여기서 한 걸음 더 나아가면 이런 것도 가능합니다.

* **전역 테마**: 시스템 전체 색상을 통일.
* **창별 강조**: 현재 활성화된 창(Active Pane)에만 좀 더 밝은 테마를 적용하고, 비활성 창은 톤을 낮춰서 **사용자의 시선이 어디에 머물러야 하는지**를 색상으로 가이드해 주는 거죠.

### "자동 모드 (Auto Mode)"

시간대에 따라 테마를 자동으로 바꿔주는 기능입니다.

* 오전 9시 ~ 오후 5시: **Soft Luxe Blue** (집중력 향상)
* 오후 5시 이후: **Mocha Mousse** 또는 **Cyberpunk** (눈 보호 및 피로 감소)

## Web Font의 사용

네, 여러 개의 웹 폰트를 사용하는 것은 당연히 가능하며, 실제 프로페셔널한 대시보드 설계에서는 **"목적에 따른 폰트 분리"**가 디자인의 완성도를 높이는 핵심 전략입니다.

`HyperPane`이나 `OmsCalendar`처럼 정보의 종류가 다양한 시스템에서는 보통 2~3개의 폰트를 조합해서 사용합니다.

---

## 1. 다중 폰트 전략 (조합 예시)

가장 권장하는 조합은 **국문용 고딕 + 숫자/영문용 폰트**의 조합입니다.

* **메인 폰트 (Pretendard)**: 시스템 전체의 기본 가독성을 담당합니다. (메뉴, 설명글, 제목 등)
* **데이터 전용 폰트 (JetBrains Mono 또는 Roboto)**: `oms-proto`의 핵심인 주문 번호, 수량, 가격 등 **수치 데이터**에 사용합니다.
* **고정폭(Monospace) 폰트**를 쓰면 숫자의 자릿수가 딱딱 맞아떨어져서 표(Table)에서 데이터를 비교할 때 훨씬 편안합니다.


* **강조용 폰트 (NanumSquare)**: 대시보드의 큰 수치나 중요한 헤드라인에만 제한적으로 사용해 임팩트를 줍니다.

---

## 2. 기술적 구현 방법 (Tailwind CSS v4 기준)

여러 폰트를 사용하려면 `index.css`의 `@theme` 영역에 각각의 변수를 등록해두고 필요한 곳에 클래스로 호출하면 됩니다.

```css
/* 1. 웹폰트들 불러오기 */
@import url("https://cdn.jsdelivr.net/gh/orioncactus/pretendard/dist/web/static/pretendard.css");
@import url("https://fonts.googleapis.com/css2?family=JetBrains+Mono:wght@400;700&display=swap");

@theme {
  /* 2. 폰트 별칭 설정 */
  --font-sans: "Pretendard", "Inter", sans-serif;
  --font-mono: "JetBrains Mono", monospace;
  --font-display: "NanumSquare", sans-serif;
}

```

이제 코드에서는 이렇게 골라 쓸 수 있습니다:

* `<div className="font-sans">일반 텍스트</div>`
* `<div className="font-mono text-blue-600">ORD-2026-0227</div>` (주문번호가 정갈하게 보임)

---

## ⚠️ 다중 폰트 사용 시 주의점 (성능 최적화)

웹 폰트는 결국 브라우저가 다운로드해야 하는 리소스입니다. 너무 많이 쓰면 화면 로딩이 느려질 수 있으니 다음 수칙을 지키는 것이 좋습니다.

1. **필요한 두께(Weight)만 선택**: `Regular(400)`, `Medium(500)`, `Bold(700)` 정도만 골라서 로드하세요. 9가지 두께를 다 받으면 용량이 커집니다.
2. **`font-display: swap` 사용**: 폰트가 다운로드되기 전에도 기본 시스템 폰트로 글자가 먼저 보이게 하여 사용자가 답답하지 않게 합니다.
3. **Local 폰트 우선순위**: `Pretendard` 같은 폰트는 사용자 PC에 설치되어 있을 확률도 있으므로, `local('Pretendard')` 설정을 앞에 두어 로딩 시간을 절약할 수 있습니다.

## 💡 HyperPane을 위한 제안

`HyperPane`의 탭 제목에는 **font-sans(Pretendard)**를 쓰고, 오른쪽 창에 띄울 주문 상세 리스트의 금액과 주문번호에는 **font-mono**를 적용해보는 건 어떨까요?

넥사크로에서는 폰트 하나 바꾸는 것도 리소스 관리가 까다로웠지만, 이제는 클래스 이름 하나로 데이터의 성격에 맞는 옷을 입혀줄 수 있습니다.

**다음에 이 폰트들을 실제로 프로젝트에 적용하는 가이드가 필요하신가요?** 아니면 또 다른 디자인 요소(아이콘, 색상 등)가 궁금하신가요?
